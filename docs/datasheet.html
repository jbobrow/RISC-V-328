RV328 — a RISC-V microcontroller in the ATmega328PB footprint

Preliminary design data. Nothing here has been measured on silicon; speed and size figures come from the third place-and-route run of the digital-first build and, where it says so, from the first full-height layout (docs/layout_results.md); speed against an ATmega328P is measured in simulation (docs/cache_study.md).

2. Feature parity with the ATmega328PB

"Digital" = implemented in RTL and exercised in simulation. "Analog macro" = the digital side exists and is tested against a behavioural model; the transistor-level block is designed and simulated (analog/README.md) and laid out as one macro (analog/layout/). There is barely room for it beside the digital layout in the half-height slot (a trial routes, but cannot be repaired). In the full-height layout the macro itself is placed, with hand-off files made from its layout and its analog lines wired (docs/build_log.md, stages 16 and 17); it still has no supply or guard rings, and the chip has not been through DRC, LVS or gate-level simulation with it.

Registers are 32 bits wide and must be read and written as words. The register description of each block is the comment header of its RTL file (rtl/periph/*.v, rtl/rv328_xip.v); sw/include/rv328.h is the C view of the same map.

Interrupt lines (Hazard3 Xh3irq numbers; lowest number first): 0 INT0, 1 INT1, 2-5 PCINT0-3, 6 WDT, 7 TC0, 8 TC1, 9 TC2, 10 TC3, 11 TC4, 12 SPI0, 13 SPI1, 14 USART0, 15 USART1, 16 TWI0, 17 TWI1, 18 ADC, 19 AC, 20 NVM. One line per peripheral: the handler reads the peripheral's flag register to find the source.

5. Clock, reset and sleep

  • Sources: RC oscillator (reset default), crystal oscillator or external clock on XTAL1, 128 kHz oscillator. Switching is glitch-free; a source cannot be selected until it has been seen running, and an oscillator cannot be switched off while it is in use. Any reset forces the RC oscillator.
  • Prescaler: divide by 1 to 256 (CLKPR), implemented as a clock gate.
  • Reset sources: power-on, RESET pin, brown-out, watchdog, software, debugger. MCUSR records the cause. The reset is held for 255 clock cycles after the last request.
  • Sleep: wfi enters the mode selected in SMCR. In power-down the oscillators stop; an enabled pin change, a level on INT0/INT1 or the watchdog restarts them asynchronously. A pin pulse shorter than the oscillator start-up time wakes the chip but is not recorded as an interrupt.
  • Keep peripheral interrupt enables and the CPU's interrupt enables consistent before sleeping: a pending peripheral interrupt that is masked in the CPU keeps the clocks running.

6. Program memory: what is different from an AVR

GF180MCU's open PDK has no embedded flash, so the program lives in a separate serial memory die (recommended: a 1 Mbit 25-series SPI EEPROM rated 1.8-5.5 V, for example 25AA1024/25LC1024 class, or an SPI NOR flash if the supply stays at or below 3.6 V) stacked or placed side by side in the same package and wired to four internal pads. The package therefore keeps 32 pins.

Consequences for firmware:

  • Code runs from a cache of 32-byte lines. A cache miss costs about 580 system clocks with NVMCFG = 0 and about 1150 with the reset value NVMCFG = 1 (29 and 58 us at 20 MHz).
  • First layout (half-height slot): 2 KB, direct-mapped. Loops that fit run at full speed. Measured on five test programs (docs/cache_study.md), this is not enough for firmware of ordinary size: a 19 KB firmware runs 5.9 times slower than with everything cached, a float-heavy logger 25 times slower than on an ATmega328P, and a serial receiver at 115200 baud loses bytes because an interrupt whose handler has left the cache takes several misses (up to 3271 clocks measured) to answer.
  • Full-height layout (routed; with the analog macro in place 20 MHz is met at all nine corners (run tgm6); with antenna diodes built in, run rmb passes the sign-off checks and is 0.26 ns short at the slowest corner; see docs/layout_results.md): 12 KB, three-way, least recently used line replaced, the first 2 KB of the program pinned, single-cycle multiplier. Measured on the same programs: within 15 % of everything cached; level with an ATmega328P on the float-heavy logger and two to four times faster on the others; no serial bytes lost; an interrupt whose handler is linked into the first 2 KB is answered in 48 clocks typically and within one line load (597 clocks measured, 30 us at 20 MHz) at worst, against a handful of clocks on an AVR. Firmware should link its interrupt handlers into the first 2 KB and set NVMCFG = 0 at start-up.
  • On either cache, the first use of any code after reset costs one miss per 32 bytes, and code that must never wait (bit-timed protocols) should run from SRAM or with its lines already loaded.
  • Writes go through the NVM controller (word or byte program, 4 KB sector erase for NOR devices). The CPU keeps running from cached code during a write; an uncached fetch waits until the write has finished.
  • In-system programming: hold RESET low and talk SPI to the memory on PB2 (CS#), PB3 (MOSI), PB4 (MISO), PB5 (SCK).

7. Known limitations of this revision

  • No scan chains or other production test structures.
  • No noise filter on RESET; no start-up delay for crystals beyond the oscillator-ready detection.
  • Peripheral registers reject nothing: byte-wide writes to a peripheral register write replicated data.
  • In the digital-first build (section 8) there is no power-on reset cell: all state, including pin directions, is undefined until RESET has been pulsed low with the clock running. RESET doubles as power-on reset and PC6 and PB6 are inputs unconditionally (RSTDISBL has no effect), the watchdog is not independent of the system clock, and MCUSR shows PORF after a pin reset.
