All results below are RTL simulation (Icarus Verilog 13). Static timing and physical checks from the layout runs are in docs/layout_results.md, together with a gate-level simulation of the routed netlist (three tests, cell delays, 20 MHz).

Method

The testbench (tb/tb.v) instantiates the complete chip - chip_top with the foundry I/O pad models, the digital core and the behavioural analog model - plus a model of the in-package serial memory. Each test is a C program (sw/tests/) compiled with clang for RV32IMC, loaded into the memory model and executed by the CPU from reset. The firmware checks results itself and reports a verdict through a register the testbench watches. External loop-back wiring between pins is selected per test.

spi SPI0 master with SPI1 slave in all four clock modes and both bit orders, two bytes per frame, slave interrupt, write collision
twi TWI0 master with TWI1 interrupt-driven slave: NACK on unknown address, multi-byte write, repeated start, multi-byte read with final NACK, slave status sequence
analog ADC codes for several inputs and references, left adjust, internal channels, free-running and timer-triggered conversions with interrupt; comparator output, edge interrupt, bandgap input, ACO pin

power idle sleep with timer wake-up, power-down with watchdog wake-up (system clock verified stopped), standby with pin-change wake-up, software reset, watchdog reset, RESET pin, reset-cause register after each

Three further configurations re-run a subset: the SRAMs replaced by the foundry macro model, and the digital-first build (analog stub, external clock, reset from an undefined power-up state).

Bugs found by these tests and fixed

  • SPI master changed MOSI half a clock early after the last bit, corrupting the slave's bit 0.
  • TWI slave counted the SCL falling edge that follows START as a data bit.
  • USART 9-bit frames with parity overflowed the receive shift register.
  • Reset-cause flags could be read back before a clear had taken effect.
  • Disabling the RC oscillator while the clock multiplexer still used it stopped the chip for good.
  • Clearing the watchdog interrupt flag restarted the watchdog period.
  • Digital-first build: the chip could drive its own reset pin from an undefined power-up state.

Cache configurations and benchmark programs

The program cache is configurable (rtl/rv328_xip.v: size of a way, one to three ways, pinned first 2 KB) and the processor has an optional single-cycle multiplier. The ten tests above pass in the first layout's configuration (2 KB direct-mapped, the default) and in the full-height layout's (make test SIMDEFS="-DRV328_CACHE_KB=4 -DRV328_CACHE_WAYS=3 -DRV328_CACHE_PIN=2 -DRV328_MUL_FAST=1").

Five benchmark programs and CoreMark run on a second bench, tb/bench_top.v, which wraps the digital core for Verilator so that millions of clocks take seconds (docs/cache_study.md). It replaces the pads, the analog macro and the serial memory by simple digital stand-ins. Cross-checks:

  • the blink benchmark takes the same 300,827 clocks between its marks on this bench and on the chip-level testbench, in the full-height configuration, with the same result value;
  • the line loads counted in the RTL equal those of an independent model of the cache run on the recorded fetch trace (159 for the logger and 760 for the full firmware on the 12 KB three-way pinned cache);
  • each benchmark built without peripherals ends with the same result values on the RV328 and on an ATmega328P in simavr.

What these results do not show

  • Timing: see docs/layout_results.md. The third layout meets 20 MHz in static timing, and the routed netlist passes basic, timers and spi at 20 MHz with typical cell delays. The full-height layout's routed netlist passes basic the same way. Wire delays, the other corners and the other seven tests have not been simulated at gate level.
  • The analog model is ideal; the tests prove the digital sequencing, not analog performance. The transistor-level analog circuits are simulated separately in ngspice (analog/README.md); they have not been simulated together with the digital core, and the behavioural model has not been updated to match their deviations (brown-out level, the ADC's sampling instant).
  • Coverage was not measured. Known untested areas are listed in docs/tapeout_checklist.md.
  • The CPU is exercised only by the test programs; Hazard3's own verification is relied on for ISA compliance.
  • Debug beyond the JTAG IDCODE read is untested.
